# Frontend smoke screenshots

Generated by `CHROMIUM_PATH=/usr/lib/chromium/chromium npm run test:ui` on an isolated headless browser. CI uses Playwright's bundled Chromium by default (`npx playwright install --with-deps chromium`). Browser data is explicit local demo data; no credentials or real mail.

- `mail-reader.png`: three-pane reader, attachment, paginated virtual list.
- `screener.png`: bulk sender selection and routing controls.
- `composer.png`: saved draft and attachment.
- `calendar-month.png`: calendar with newly created event.
- `contacts.png`: contact cards including newly created person.
- `settings-dark.png`: AI enablement with separate unchecked consent.
- `mail-light.png`: saved light theme.
- `mail-mobile.png`: narrow responsive reader.
- `theme-picker-light.png`: portable static palettes on a non-Omarchy browser.
- `theme-picker-omarchy.png`: Follow Omarchy and portable palettes (mocked native IPC).

Eleven smoke scenarios also exercise keyboard movement/search, draft reopen/queue, calendar month/week/day/edit/delete, contacts edit/delete/unified conversations, recovery review, narrow composer, revision-aware RSVP, and all-day exclusive date ranges.

`sync-status` is native-only: updates account status and reloads messages without resetting the open composer/draft. Native event delivery requires desktop integration validation.

Theme checks exercise all 22 stock and 15 custom snapshots, accent-label contrast, persisted selection, live updates, explicit overrides and missing-Omarchy fallback.
